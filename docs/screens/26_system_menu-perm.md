# `/system/menu-perm` — 메뉴 접근 권한

화면 ID `sys-menu`. `MenuPermView` → `useMenuPermController` → `systemRepository.loadMenuPerms`.

## 부서 × 화면

`MenuPermGrid`가 공통 `TabulatorGrid`로 표시한다. 메뉴 그룹·명칭·순서는 공통 메뉴 정의에 맞춘다. 검색 필터는 제공하지 않는다. 그룹의 +/− 버튼으로 펼침·접기를 전환하며 권한 저장 후에도 접힌 상태를 유지한다.

- 열 너비를 직접 조절하고 최소 너비를 유지한다. 가로 스크롤은 표 내부에 제공하며 헤더와 본문이 함께 이동한다. 높이 620px, 넘치는 행은 세로 스크롤한다.
- 각 그룹의 첫 행에는 부서별 전체 허용/전체 해제 버튼을 둔다. 그룹 일괄 변경은 접힘 여부에 관계없이 해당 그룹 전체에 적용한다.
- 개별 화면의 체크박스는 기존 `PUT /system/menu-perms`를 호출한다. 그룹 버튼도 현재 그룹에 속한 화면 ID별로 같은 API를 호출한다. 서버의 과거 그룹명에 의존하지 않으며 중간 실패 시 저장 건수를 알리고 실제 상태를 다시 조회한다.
- 통합관리자 부서는 전 권한으로 표시하며 변경할 수 없다.
- 하단은 접힌 항목을 포함한 전체 화면의 허용 수를 계산한다. 그룹 일괄 행은 집계에서 제외한다.
- 저장 중 중복 입력을 막고, 실패하면 이전 권한을 유지한다. 재조회 중에도 표를 제거하지 않아 펼침 상태와 열 너비를 유지한다.
- 부서 권한 복사와 엑셀 다운로드는 유지한다. 계정별 추가 허용은 계정 관리에서 별도로 설정한다.

`부서별 적용 현황` 카드는 삭제했으며 관련 `GET /system/menu-perms/dept-status` 조회도 제거했다. 상단 요약은 매트릭스 데이터로 계산한다.

## 검증

`WEB_URL=http://localhost:8092 node tests/system/menu-perm-browser.cjs`

브라우저 fixture로 최신 메뉴 그룹·명칭, 필터 제거, 펼침·접기 유지, 개별/그룹 변경 요청, 실패 시 기존 상태 유지, 통합관리자 잠금, 좁은 화면의 마지막 열·헤더 동기 스크롤, 삭제된 카드/API 미호출을 확인한다. 실제 부서 권한은 변경하지 않는다.
