## 부서 × 화면

`MenuPermGrid`가 공통 `TabulatorGrid`로 표시한다. 메뉴 그룹·명칭·순서는 공통 메뉴 정의(`menu.js`, 대그룹 8개 — AI 어시스턴트 · 대시보드 · 생산 및 품질 관리 · 보고서 · 자연어 질의 이력 · 용어 사전 · 이상 알림 · 시스템관리)를 따른다. 검색 필터는 제공하지 않는다. 그룹의 +/− 버튼으로 펼침·접기를 전환하며 권한 저장 후에도 접힌 상태를 유지한다(접힘 상태는 컨트롤러가 들고 있어 엑셀 「조회 목록」 에도 쓴다).

- 열: 메뉴 그룹 180/140 · 화면 350/220 · 구분 140/120 · 개인 허용 120/110 · 부서마다 머리글 그룹 「부서명 · n명」 아래 「조회」 100/90 · 「쓰기」 100/90. 열을 줄이거나 숨기지 않고 표 내부에서 가로로 스크롤하며 헤더와 본문이 함께 이동한다. 높이 620px.
- 화면 이름에 관리 화면 5종(2026-10-03 2차 — 전사 자연어 질의 이력 포함)은 `(관리)`, 전사 공통 화면(`chat-history`·`gloss-view`)은 `(전사 공통)` 을 붙인다(서버 `admin`·`common`).
- 쓰기 칸은 조회가 켜져 있어야 켤 수 있다. 쓰기를 켜면 `PUT /system/menu-perms {perm:'WRITE'}` 이고 서버가 조회도 함께 켠다. 조회를 끄면 「쓰기 권한도 함께 회수됩니다」 확인 창을 거쳐 `perm:'READ', allowed:false` 를 보낸다(서버는 행을 지워 쓰기도 회수).
- 잠금(판정 근거는 서버 응답만 쓴다 — `depts[].locked` · `screens[].admin` · `canEditAdminScreens`)
  - 통합관리자 열: 머리글 「전 권한」, 모든 칸 잠금.
  - 미배정 열: 머리글 「미배정 · n명 / 고정(5화면) · 변경 불가」, 모든 칸 잠금(대시보드 3 · 덕반장 AI · 자연어 질의 이력 조회 전용, 쓰기 없음).
  - 관리 화면 4종(`sys-account`·`sys-menu`·`sys-data`·`sys-gw-dept`) 행: 통합관리자가 아니면 모든 부서 칸 잠금. 통합관리자가 바꿀 때는 「n명에게 화면을 엽니다/닫습니다」 확인 창을 띄우고, 자기 부서의 `sys-menu` 조회를 끄면 「저장하면 이 화면에서 나가게 됩니다」 를 덧붙인다. `sys-audit` 은 잠그지 않고 확인 창만 띄운다.
- 관리 화면이 든 그룹 일괄·관리 화면을 바꾸는 복사를 통합관리자가 아닌 사람이 부르면 서버는 403 `E-AUTH-002` 로 거부한다(API 2단계 계약, 공통 9.7). WEB 은 미리 잠그고, 거부되면 서버 메시지를 토스트로 보인다.
- 그룹 일괄: 각 그룹 첫 행에 부서·칸(조회/쓰기)별 「전체 허용/전체 해제」 버튼을 둔다. `PUT /system/menu-perms/group {deptId, groupId, allowed, perm, includeActions:false}` 1회로 처리한다. 동작 행(예: 업로드 리포트 업로드)은 바꾸지 않고 그룹 상태 계산에서도 뺀다. 관리 화면이 든 그룹(시스템관리)은 통합관리자가 아니면 버튼을 잠근다(서버도 요청 전체를 거부).
- 하단은 접힌 항목을 포함한 전체 화면의 칸별 허용 수를 계산한다.
- 저장 중 중복 입력을 막고, 서버가 거부하면(409 등) 이전 권한을 유지하고 서버 메시지를 토스트로 보인다. 네트워크 예외는 「저장하지 못했습니다. 권한을 다시 확인해 주세요」 토스트 후 다시 읽는다. 재조회 중에도 표를 제거하지 않는다.
- 개인 허용 열(MNP-06): `grantCounts` 의 건수를 `n명 ▸` 버튼으로 보이고, 누르면 그 화면에 추가 허용을 가진 계정 명단(이름 · 사번 · 부서)을 띄운다. 명단 `grants` 는 서버가 `sys-menu` 권한 요청에만 주므로, 없으면 건수만 안내한다. 부서 조회를 끌 때 같은 부서에 개인 허용 계정이 있으면 저장 뒤 토스트에 「개인 허용 n명은 계속 접근합니다 — 계정 관리에서 회수하세요」 를 덧붙인다.
- 부서 머리글(MNP-09): 「부서명 · n명」, 계정 0명 부서는 흐리게 그린다. 미배정 「고정(5화면) · 변경 불가」, 통합관리자 「전 권한」.
- 상위·하위 화면(MNP-10): 상위 화면은 서버 `parentId`(없으면 메뉴 정의의 parent). 상위 화면 조회를 끌 때 켜져 있는 하위 화면·동작이 있으면 「이 화면만 끄기 / 함께 끄기」 창을 띄우고, 함께 끄기는 상위 → 하위 순서로 단건 요청을 보낸다. 하위만 켜져 있고 상위가 꺼진 칸에는 ⚠ 표시(title 에 이유)를 붙인다.
- MNP-14(판정 뷰에 메뉴 그룹 사용 여부 반영)는 DB 뷰 변경이라 WEB 코드 변경이 없다. 그룹이 꺼지면 그 화면이 `/auth/me` menuPerms 와 매트릭스에서 함께 빠진다.
- 동작 행(MNP-05): 구분을 「동작(쓰기)」 로 표시하고 행 배경을 옅게 나눈다. 판별은 서버 `kind:'ACTION'`(없으면 메뉴 정의의 action).

## 부서 권한 복사 (2단계) — 제거됨(2026-10-07, 「부서 추가」 로 대체)

`MenuPermCopyForm`. 원본·대상 기본값은 비어 있고, 선택지는 「부서명 (계정 n명)」 으로 표시한다. 미배정은 원본·대상 모두에서, 통합관리자는 대상에서 뺀다.

1. 「미리보기」 — 빈 값이면 필수 오류만 보이고 요청하지 않는다. `POST /system/menu-perms/copy {fromDeptId, toDeptId, dryRun:true}` 응답으로 영향 계정 수, 추가(쓰기 포함 건수)·회수 목록, 관리 화면 변경을 보인다.
2. 관리 화면이 바뀌면(`requiresSuperAdmin`) 통합관리자가 아닌 사람에게는 「통합관리자만 실행할 수 있습니다」 를 보이고 「복사」 를 잠근다. 그 밖에는 「위 내용을 확인했습니다」 를 체크해야 「복사」 가 켜진다.
3. 「복사」 — `{dryRun:false, expectedHash}`. 미리보기 뒤에 권한이 바뀌어 서버가 409 로 거부하면 미리보기를 다시 불러온다.

## 2026-10-03 조회/쓰기 통합 (DB · API · WEB)

사용자 결정으로 메뉴 접근 권한의 「조회」 · 「쓰기」 두 칸을 「접근」 한 칸으로 합쳤습니다. 화면에 접근할 수 있으면 그 화면의 모든 동작(등록 · 수정 · 삭제 · 상태 전환)을 쓸 수 있습니다. 예외는 미배정 계정 하나로, 어떤 화면에서도 쓰기 동작을 할 수 없습니다(서버 규칙). 통합관리자는 전부 통과합니다.

- 표: 부서마다 한 칸입니다. 머리글은 「부서명 · n명」(시스템 부서는 둘째 줄 잠금 표기), 칸은 접근 체크입니다. 필드는 `dept_{deptId}`(예전 `dept_{id}_read` · `dept_{id}_write` 는 없앴습니다). 너비 140 / 최소 110.
- 그룹 일괄: 부서별 단추 하나입니다(「전체 허용 / 전체 해제」). 동작 행 제외는 그대로입니다.
- 요청: `PUT /system/menu-perms {deptId, screenId, allowed}` · `PUT …/group {deptId, groupId, allowed, includeActions:false}` 에서 `perm` 을 뺐습니다. 응답 `writeMatrix` · `grants[].write` 는 읽지 않습니다.
