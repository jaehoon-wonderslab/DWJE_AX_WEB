# AI 통합 대시보드 기간 조회 — 사용성 검토 및 수정 (2026-09-07)

## 오류 재현

최근 4주 조회 시 `ReferenceError: EmptyState is not defined`가 발생하여 화면 전체가 사라졌다. 7일 이하는 시간대 매트릭스를, 그보다 긴 구간은 안내 컴포넌트를 표시하는데 안내 컴포넌트 import가 빠진 것이 원인이다. 브리핑·원인 분석 응답을 비워도 재현되었으며 Ollama 상태와 무관하다.

하루만 직접 조회하면 서버가 `00:00` 형식을 반환한다. 기존 매트릭스가 `09-04 00시` 형태만 해석해 실측 칸이 비는 문제도 확인했다.

## 사용성 검토와 결정

시간 범위와 집계 간격은 별개다. 기존 ‘집계 단위’ 옵션은 실제로 최근 7일·4주·3개월 범위를 지정하고, 차트 간격은 서버가 범위에 따라 시간/일로 결정한다. 따라서 ‘주별’을 선택했다고 차트가 주별로 묶인다고 안내하면 오해를 만든다.

- 이름을 **조회 기간**으로 바꾸고 **최근 7일 / 최근 4주 / 최근 3개월 / 직접 선택**을 제공한다.
- 빠른 기간은 마지막 실적일을 기준으로 잡는다. 날짜 수정은 직접 선택으로 바뀌며 입력 중인 날짜를 자동 보정하지 않는다.
- 모든 기간 조건은 **조회 버튼으로 한 번에 적용**한다. 편집 중 조건과 실제 조회된 기간을 구분해 표시한다.
- 빈 날짜·유효하지 않은 날짜·역전·92일 간격 초과를 안내하며 잘못된 요청을 전송하지 않는다.
- 차트 제목·각주·이미지 내려받기는 서버의 실제 집계 간격과 적용된 기간을 사용한다.

여러 필터를 설정하고 결과를 받는 데 시간이 걸리는 화면에는 일괄 적용 방식이 적합하다. NN/g의 [필터 적용 방식 가이드](https://www.nngroup.com/articles/applying-filters/)와 Grafana의 [시간 범위 제어](https://grafana.com/docs/learning-paths/visualization-logs/time-range-refresh/)를 참고했으며, 본 화면의 API가 자동으로 간격을 결정한다는 점을 반영했다.

## AI 서비스가 꺼진 경우

일반 실적 조회는 AI 분석을 자동 호출하지 않는다. **AI 분석 요청** 버튼으로 조회된 기간의 브리핑을 요청하고, 준비되었을 때 원인 분석을 순서대로 요청한다. 브리핑 서비스가 꺼져 있으면 같은 모델에 두 번째 요청을 보내지 않는다.

결과가 없거나 서비스가 중단되면 ‘현재 AI 분석 결과가 없습니다’라는 일반 안내를 표시한다. 이를 생산·품질 실적 오류로 취급하지 않는다. 새 기간 조회·실적 새로고침 시 이전 분석 결과를 지우고, 늦게 도착한 이전 기간의 결과는 무시한다. Ollama 프로세스는 시작하거나 종료하지 않는다.

## 수정 범위

- 누락된 EmptyState import와 하루 조회 시간 문자열 처리.
- AI 페이지 전용 기간 입력 모델·컨트롤러·뷰.
- AI 미제공 안내 문구.
- AI 페이지에서 결과를 사용하지 않던 생산 실적 API 2개 호출 제거.
- 기존 기간 필터 테스트를 새 일괄 적용 흐름으로 조정.

API·DB 변경은 필요하지 않다.
