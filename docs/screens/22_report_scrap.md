| 항목 | 값 |
| :--- | :--- |
| URL | `/report/scrap` |
| 화면 ID | `rpt-scrap` |
| 라우트 파일 | `app/(main)/report/scrap/index.jsx` |
| MVC | `domains/report/view/ScrapReportView.jsx` · `controller/useScrapReportController.js` |

| 접근 권한 | 품질보증팀 · 생산관리팀 · 경영진 · 통합관리자 |

폐기 수량을 **「품질팀_폐기보고서」 양식**(`Web 프로토타입/보고서 스크린샷/품질팀_폐기보고서.png`)
그대로 채웁니다. 금액 열은 원가(**`price`**) 열람 권한이 있는 계정에만 표시됩니다.

> **2026-09-04 — 결재·발행·인쇄를 앱에서 하지 않습니다.**
> 사용자 지시: *"템플릿 및 내용만 채워줄 것이고, 결재선/발행/인쇄는 엑셀로 자료를 받으면,
> 로컬파일에서 편집/결재/인쇄 등등을 진행 할 것임"*
>
> 5단계 작성 위저드(RP-07, `rpt-scrap-new`)를 접고 **한 화면**으로 합쳤습니다.
> 서버의 초안 CRUD·수기 행·금액 산정·결재선·검토요청·발행·출력·인쇄 14건은 제거됐고,
> 되살리지 않습니다. 발행이 없으므로 **문서번호도 없습니다**(빈칸으로 두고 엑셀에서 채웁니다).

## 2. 화면에 출력해야 하는 정보

`GET /reports/scrap/mes-vouchers` 로 전표를 받아 **화면에서 묶습니다.**
발생 구분은 서버가 한 번에 하나만 받으므로 체크한 것마다 부르고 합칩니다.

| 칸 | 값 | 출처 |
| :--- | :--- | :--- |
| 발생수량 | 전표 `qty` 합 | 계산 |
| 모델명 | 최다 모델 + `외 N종` | 계산 |
| 발생공정 | 전표 `process` 중복 제거 (4곳 이상이면 `전 공정`) | 계산 |
| 발생일자 · 제조일자 | 전표 `occurDate` 최소 ~ 최대 | 계산 |
| 주요 모델별 발생수량 | 모델별 합, 내림차순 상위 8 | 계산 |
| 문서번호 · 결재란 · 검토 의견 | **빈칸** — 엑셀에서 채웁니다 | — |

### 세 갈래 중 둘만 근거가 있습니다

양식은 총 수량을 「공정불량 / 불용 재고 / Loss」 로 나눕니다. 서버 `scrapKind` 는 둘뿐입니다.

| 갈래 | 뜻 | 2024-04 실측 |
| :--- | :--- | ---: |
| `DEFECT` → 공정불량 | 불량 이력이 붙는 전표 | 746,039 |
| `OTHER` → 그 밖 (불용 재고 · Loss) | 안 붙는 전표 — 잔여 원재료·재고 처분 등 | 445,789 |

**불용 재고와 Loss 를 가르는 근거가 원천에 없습니다.** `hist_type` 은 `SCRAP` 하나뿐이고
남은 단서는 `remark` 자유 텍스트뿐입니다. 키워드로 나누면 근거 없는 숫자가 되므로 나누지 않고,
`OTHER` 를 한 줄로 두고 **「▶ 폐기 사유」 절에 `remark` 별 수량을 그대로 보여 줍니다** —
세 갈래 규칙을 정하려면 현업이 이 목록을 봐야 하기 때문입니다.

### 엑셀에서 손으로 채우는 칸

| 칸 | 왜 |
| :--- | :--- |
| 문서번호 | 발행이 없어졌습니다 |
| 업체명 | `tb_pop_stock_hist` 에 거래처 컬럼이 없습니다 |
| 폐기 금액 | 단가 표(`ax.tb_prod_item_price`)는 살아 있으나 **0행** |
| 결재란 · 검토 의견 | 결재를 앱에서 하지 않습니다 |

### 수량 부호

원천은 재고 감소라 `qty` 가 음수인데 **서버가 양수로 뒤집어 내립니다**(2026-09-04).
화면에서 또 뒤집지 않습니다.

### 데이터가 있는 구간

`hist_type=SCRAP` 기록이 **2020-03-10 ~ 2024-05-24** 에만 있습니다. 2025~2026 폐기 기록은
원천에 없습니다(재이관으로 해결되지 않습니다). 확인은 `2024-04-01 ~ 2024-04-30`(187건)으로 합니다.
