## 0. 항목 × 부서 (2026-10-07 — 현재 화면)

- 표 하나: 행 = **항목**(화면에 보이는 이름. 같은 뜻의 API 데이터 키 여러 개 — `model/dataItemModel.js`), 열 = 항목 · **출력 화면**(그 항목이 나오는 화면 전부) · 부서마다 열람 체크(`view/ItemPermGrid.jsx`).
- 체크 = 그 부서가 그 항목을 봅니다. 누르는 즉시 `PUT /system/data-fields/item-perms {name, attrs, perms:{deptId:bool}}` 1건으로 저장합니다(응답 전 두 번째 클릭은 요청 없음, 표를 다시 만들지 않음).
  서버가 그 키들을 항목 하나로 모으고(이미 그 키만 가진 항목이면 재사용) 그 부서의 열람을 바꿉니다.
- 칸 상태: 키를 모두 볼 수 있으면 체크, 하나도 못 보면 빈칸, 키마다 다르면 반쯤 채운 체크(누르면 그 부서가 모두 보게 맞춤). 통합관리자 열 전 권한 · 미배정 열 0건 고정(잠금).
- 가릴 수 없는 항목(공용 키 · 시스템 값)은 칸을 잠그고 항목 칸에 「가릴 수 없음 (공용 키)」 처럼 이유를 적습니다.
- 머리글 필터(항목 · 출력 화면), 쪽 나누기 10 · 25 · 50(기본) · 100, 바닥 줄 = 부서별 볼 수 있는 항목 수.

## 2. 부서 × 종류 표 (`GET /system/data-perms`)

| 열 | 내용 | width / minWidth |
| :--- | :--- | :--- |
| 데이터 항목 | 이름 + 기본 7종 `(기본)` | 170 / 140 |
| 분류 | `categoryNm` | 110 / 100 |
| 적용 | `적용 중` / `미적용` + 「켜기」/「끄기」. 기본 7종은 `적용 중 (고정)` 이고 끄기 버튼이 없음(DTP-05) | 110 / 100 |
| 포함 데이터 | `desc`, 없으면 가리는 값을 화면 열 제목으로 요약(`model/dataFieldModel`, DTP-07) | — / 260 (widthGrow 2) |

- 표가 카드보다 넓으면 표 안에서 가로로 스크롤하고 헤더와 본문이 함께 움직입니다. 열을 줄이거나 숨기지 않습니다.
- 셀 체크 → `PUT /system/data-perms {deptId, fieldKey, allowed}` → 목록 + `/auth/me` 재조회. 저장 중에는 칸을 잠그고(「저장 중…」) 응답 전 두 번째 클릭은 요청을 만들지 않습니다. 재조회 중에도 표를 다시 만들지 않아 스크롤 위치가 유지됩니다.
- 서버가 거부하면(409 등) 체크 상태를 유지하고 서버 메시지를 토스트로 보입니다. 네트워크 예외는 토스트 후 다시 읽습니다.
- 잠금(판정은 서버 응답 `depts[].locked` 만 씁니다)
  - 통합관리자 열: 전 권한, 모든 칸 잠금.
  - 미배정 열: 데이터 권한 0건 고정(R-11). 응답 `matrix` 와 관계없이 모든 칸이 꺼진 채 잠기고, title 은 「미배정 부서는 데이터 접근 권한이 없습니다(모든 종류 비공개)」.
- 빈 데이터면 「데이터 종류가 없습니다 — 항목 관리에서 만드세요」, 최초 조회 실패면 오류와 「다시 시도」.

- 적용 전환(DTP-04): 「켜기」 는 확인 창에 가리는 값 수·이름, 열람 허용 부서 수, 가려지는 부서(계정 수, 미배정은 항상 포함 · 「미배정은 고정」)를 보인 뒤 `PATCH /system/data-fields/{key}/apply {on}` 을 부릅니다. 가리는 값이 없는 종류는 켤 수 없습니다. 미적용 행은 흐리게 그리고, 체크 title 에 「미적용 — 체크해도 아직 가려지지 않습니다」 를 붙입니다.

## 2-1. 계정으로 확인 · 최근 변경 이력 (DTP-10)

- 계정으로 확인: 사번을 넣고 「확인」 → `GET /system/data-perms/preview?empNo=` 결과를 종류 · 적용 · 결과(`원본 노출` / `●●●● 비공개` / `미적용 — 가리지 않음`) 표로 보입니다. 서버가 행마다 `applied` 와 `masked`(= applied && 열람 불가)를 줍니다(API 3단계). `applied` 가 없는 구 응답이면 매트릭스의 적용 여부로 대신합니다. 이름 검색은 계정 목록 권한(sys-account)이 필요해 사번 입력으로 두었습니다.
- 최근 변경 이력: `GET /system/perm-logs?actType=DATA_PERM&size=20`, 시각 · 대상 · 변경 내용 · 수행자. 저장할 때마다 다시 읽고, `sys-audit` 권한이 있으면 「보안 감사 로그에서 더 보기」.
- 두 카드 모두 공통 `TabulatorGrid autoWidth` 이고 좁은 화면에서는 표 안에서 가로로 스크롤합니다. 넓은 화면은 나란히, 1100px 아래는 위아래로 놓습니다.

## 3. 읽기 전용

`/auth/me` 의 `writePerms` 에 `sys-data` 가 없으면 매트릭스 체크와 「항목 관리」 의 체크·종류 선택·저장·삭제를 모두 비활성으로 두고 「읽기 전용 — 이 화면의 쓰기 권한이 없습니다. 전산팀에 요청하세요.」 를 보입니다. 「항목 관리」 는 열어서 볼 수 있습니다. 엑셀 다운로드는 조회 권한으로 판정하므로 그대로 쓸 수 있습니다(R-10).

## 4. 항목 관리 — 화면 보고 가리기 (`DataFieldManager`)

- 화면 선택지에서 시스템관리 화면(계정 관리 · 메뉴 접근 권한 …)을 뺍니다(DTP-01).
- `GET /system/data-fields` 응답의 `reservedAttrs`(로그인·권한 응답·공통 키)에 든 필드는 체크할 수 없고 「가릴 수 없음」 을 보입니다. WEB 에 예약어 목록을 따로 두지 않습니다.
- 저장은 `PUT /system/data-fields/mapping` **1회**입니다(DTP-02). 서버가 새 종류 등록 · 새 종류 부서 허용(통합관리자·미배정 제외) · 필드명 이동 · 명시한 종류 적용을 한 트랜잭션에서 처리하고, 하나라도 실패하면 전부 되돌립니다. 실패하면 서버 메시지를 보이고 고른 내용(바꾼 열·새 종류)을 그대로 둡니다.
- 꺼져 있던 종류에 값을 붙여도 자동으로 켜지 않습니다. 응답 `notApplied` 가 있으면 「「OO」 종류는 미적용 상태입니다 — 바깥 표에서 적용을 켜야 가려집니다」 를 안내합니다. 새 종류만 요청에서 `apply:true` 로 켭니다.
- 바꾼 열이 있는데 화면을 바꾸거나 모달 아래 「닫기」 를 누르면 확인 창을 띄웁니다(DTP-14). 바깥 영역·× 로 닫는 것은 공통 모달이 가로채지 못해 막지 못합니다.
- 종류 편집(DTP-11): 종류 목록의 「편집」 → 이름(필수 50자) · 설명(300자)을 `PUT /system/data-fields/{key}` 로 저장합니다(분류는 2026-10-07 없앰 — 아래). 길이는 화면에서 먼저 막고, 서버 오류는 토스트로 보입니다. 설명을 비우면 빈 값을 그대로 보냅니다. 새 종류 만들기도 같은 칸을 받습니다. key 는 바꾸지 않습니다.
- 상태·요청은 `useDataFieldManagerController` 가 맡고, 뷰는 그리기만 합니다.

  - 뺀 것: 「값 이름」 열(보이는 화면 줄에 키를 함께 적음 — DB 칼럼명이 아니라 API 응답 키라는 설명을 사용 순서 아래에 둠), 「지금 상태」 열(체크로 표현), 「바깥 표의 행」 · 「(새 행)」 · 「2단계에서 처리」 문구. 검색(항목 이름 · 값 이름 · 화면)과 보기(전체 · 일부만 가림 · 가리는 · 가리지 않는 · 고를 수 없는) 필터.

- 저장: 바뀐 항목의 고를 수 있는 값 이름을 모두 모아 `PUT /system/data-fields/mapping` 1회 — `screenId: '항목 관리 · 항목 기준'`, 메모 `항목 · {항목 이름}`, 새 행은 `newFields`. 빈 행 지우기는 그 뒤 `DELETE /system/data-fields/{key}`(실패해도 가리기는 이미 풀림).
- 모달 닫기 확인의 「바꾼 수」 는 화면별 탭 + 항목 탭 합계입니다.
- 시험: `tests/system/data-item-model.cjs`(묶기 · 상태 계산), `tests/system/data-perm-browser.cjs`(항목 탭 — 종류 선택 칸 없음 · 공용 키 제외 · 잠금 · 불량률 체크 = 새 행 + 값 이름 2개 매핑 1건 · 체크 끄기 = 풀기).
- (같은 날 4차 피드백) 항목 탭 표
  - 열: **항목** · **출력 화면**(화면 이름만 줄마다 — 열 이름 · API 데이터 키는 뺌) · **가리기** · **부서별 설정 현황**.
  - 부서별 설정 현황은 안내 문장 없이 값만: `비공개: 부서 · 부서 …`(그 데이터 항목을 못 보는 부서 — 통합관리자는 늘 봄, 미배정은 늘 못 봄) · `모든 부서 열람` · `미적용` · `저장 후 부서 설정`(새 데이터 항목) · `가릴 수 없음` · `—`(체크 안 함).
    부서 목록은 모달이 `GET /system/data-perms` 를 직접 읽고, 항목 저장 뒤 다시 읽습니다.
  - 검색 · 보기 선택 상자를 없애고 표 머리글 필터로: 항목(이름 · 다른 이름 · API 키), 출력 화면, 가리기(목록: 가림 · 안 가림 · 일부 화면만 가려짐 · 가릴 수 없음), 부서별 설정 현황.
  - 쪽 나누기 10 · 25 · 50(기본) · 100.
  - 모달 최대 폭 980 → 1280px(가로 스크롤 없음, 1616px 화면에서 확인).
- (같은 날 5차 피드백) 화면별 보기 · 가리기 종류 탭
  - **화면별 보기**: 「③ 종류」 열을 없애고 항목 탭과 같은 **항목 단위 체크**로 바꿨습니다(저장 전 변경 · [저장] 공유). 머리글 번호 없음.
    열: 열 이름 · 가리기 · **가려지는 다른 화면 목록**(「외 n곳」 없이 모두) · 부서별 설정 현황. 화면을 바꿔도 고른 내용이 남아 확인 창을 없앴습니다.
  - **가리기 종류 → 「묶음」**: 바깥 표의 한 줄(데이터 항목) = 묶음 하나. 열: 묶음 · 든 항목(항목 이름) · 부서별 설정 현황 · 관리([편집] · 빈 묶음만 [삭제]).
    [편집] 은 이름 · 설명 · 든 항목(「항목 넣기」 · [빼기] · [되살리기], 키 이름 없이 항목 이름과 출력 화면)이고, 저장은 항목을 API 데이터 키로 풀어 기존 `PUT mapping` + `PUT /data-fields/{key}` 로 보냅니다.
    항목에 묶이지 않은 키(서버 시드)는 그대로 둡니다.
  - 컨트롤러에서 화면 · 열 단위 상태(draft · newKinds · toggleField · save · valueCandidates …)를 걷어냈습니다.
- (같은 날 6차 피드백)
  - 화면별 보기: 첫 열 「열 이름」 → 「항목」, 요약 「이 화면의 n개 항목 중, m개를 가리고 있습니다.」, 표 없는 화면 안내 문장 삭제.
  - 부서별 설정 현황: 「비공개:」 머리말 삭제 — 칸의 부서 목록은 그 항목을 못 보는 부서입니다(사용 순서 ③ 에 적음).
  - **항목별 [부서 설정]**: 체크한 항목(저장 후 · 적용 중)의 칸에 단추. 창에서 볼 수 있는 부서를 체크합니다(통합관리자 「전 권한 · 고정」, 미배정 「항상 못 봄 · 고정」).
    저장은 바뀐 부서만 `PUT /system/data-perms {deptId, fieldKey, allowed}` 한 건씩, 실패하면 거기서 멈추고 메시지를 보입니다.
    권한은 묶음 단위라 같은 묶음의 다른 항목에도 함께 적용됩니다 — 창 부제에 그 항목들을 적습니다. 묶음 탭의 각 줄에도 같은 단추가 있습니다.
- (같은 날 7차 피드백) 부서별 설정 현황은 **볼 수 있게 설정된 부서만** 적습니다(통합관리자 · 미배정 부서는 설정 대상이 아니라 빼고 적음). 한 곳도 없으면 「미배정」. 항목 · 화면별 보기 · 묶음 탭 같음.
- (같은 날) 「가릴 수 없음」 에 이유를 붙입니다 — `가릴 수 없음 (공용 키)`(화면마다 다른 값을 담는 키, `dataItemModel.GENERIC_ATTRS`) · `가릴 수 없음 (시스템 값)`(서버 `reservedAttrs`) · 둘 다면 `(공용 키 · 시스템 값)`. 항목의 키가 모두 이 둘일 때만 가릴 수 없습니다.
