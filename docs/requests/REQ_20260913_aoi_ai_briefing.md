## 0. 한 줄 요약

AOI 판정 기록에서 **어느 치수가 불량을 만들었는지 규칙으로 계산**하고, 그 결과를 sLLM 이 문장으로 옮겨
화면 상단에 브리핑으로 보여 준다. **숫자는 규칙이 만들고 문장만 AI 가 만든다.**

## 2. 데이터 현실

`EDGE.dbo.TB_SAMSUN_DIMENSION` — 2026-09-11·09-13 실측 기준.

```
한 행  = 제품 1개의 측정 1회 (SEQ = 회차, 시리얼마다 1부터)
치수   = FAI1~FAI45(S110) / FAI1~FAI58(S120) 가 한 행에 가로로
PASSED = 그 행 전체의 합부 ('1' 통과 / '0' 불량)
규격   = 테이블에 없음.  항목 이름 = 없음.
COMMENT = 호기(#7 B 등 8종). 불량 사유가 아님
시리얼당 SEQ 2,000~3,800개 · 설비 하루 약 6만 행
```

한 시리얼의 SEQ 중 하나라도 `PASSED='0'` 이면 그 시리얼은 불량이다.
**그 결과 모든 시리얼이 불량으로 나온다.** 합부로는 줄을 세울 수 없으므로
목록의 정렬·표시는 **불량 SEQ 비율**과 **주원인 치수**를 쓴다.

## 3. 규격을 데이터에서 되찾는다 (검증 완료)

테이블에 규격이 없지만 `PASSED` 라벨이 대량으로 있다. 측정 분해능이 유한해
**합격이 규격선에 붙어 쌓이고 그 다음 눈금부터 불량**이 되는 포화가 관측된다.
분해능은 작업장마다 다르다(S120 `0.001` · S110 `0.0001`).

```
FAI1   합격 449행이 정확히 0.040,  불량 최솟값 0.041   → 상한 0.040
FAI10  합격 438행이 정확히 22.880, 불량 최솟값 22.881  → 상한 22.880
```

### 하면 안 되는 방법

표본의 min·max 를 규격으로 쓰면 **틀린다.** 다른 표본에 적용했을 때 오탐이
MQ-008 다음날 0.8%, 이틀 전 24%, MQ-003 60%, MQ018 74% 로 튄다. 그날 그 설비의 산포일 뿐이다.

### 확정 규칙

여러 날짜 표본에서 **분해능 단위까지 완전히 일치하는 한계만** 확정한다.
확정되지 않은 FAI 는 **한계 없음**으로 둔다.

> `(작업장, 설비)` 별 최근 7일 합격 행의 FAI별 max·min 에 대해,
> 불량 값의 최솟값이 `max + resolution` 이고 그 값에 놓인 합격 행이 **20건 이상**이면 상한 확정.
> 하한도 같은 식. — 기준값 20 과 7일 창은 7일 표본으로 한 번 더 검증한 뒤 고정한다.

### 한계는 (작업장, 설비) 단위다

처음에는 작업장 단위로 봤다. S120 에서는 MQ-008·MQ-003·MQ018 이 같은 상한을 공유해 그렇게 보였다.
**S110 에서 깨졌다** — GP-009·013·014 는 같은 세트가 나오지만 **GP-015 는 다른 규격**이 걸려 있다(다른 제품으로 추정).
한 단계 내려 `(wc_cd, eqpt_cd)` 단위로 관리한다.

### 작업장마다 다른 것

| 항목 | S120 (MQ-*) | S110 (GP-*, 도금) |
| :--- | :--- | :--- |
| 사용 FAI | 58개 | 45개 |
| 측정 분해능 | 0.001 | **0.0001** (소수 4자리) |
| 이탈 방향 | 상한 초과 **91%** | **하한 미달 62%** · 상한 24% · 양쪽 13% |
| 단일 항목 환원 | 80.6% | 69.3% |
| COMMENT | 호기 | 지그 번호 (지그가 달라도 한계는 같음) |

**상한만 보면 S110 은 절반 이상을 놓친다.** 양방향으로 본다.

### S120 확정 한계 (5표본 검증)

| 구분 | 값 |
| :--- | :--- |
| 상한 9개 | FAI1 `0.040` · FAI2 `24.435` · FAI4·5 `24.622` · FAI7 `19.859` · FAI10·11 `22.880` · FAI32 `4.222` · FAI52 `3.760` |
| 하한 2개 | FAI51·52 `3.560` |

| 검증 항목 | 결과 |
| :--- | ---: |
| 합격 행 오탐 | **0%** |
| 불량 설명률 (MQ-008 09-11) | 98.4% |
| 〃 (MQ-008 09-10 / MQ-003) | 96.0% / 96.1% |
| 〃 (MQ-008 09-09 / MQ018) | 80.4% / **60.1%** |
| 위반 FAI 1개인 행 | **80.6%** (2개 12.5% · 3개 이상 6.9%) |
| 이탈 방향 | 상한 초과 **91%** |

### S110 확정 한계 (6표본 검증)

세트를 어느 범위에서 뽑느냐로 결과가 갈린다.

| 세트 기준 | 설명률 | 판단 |
| :--- | :--- | :--- |
| 6표본 전부 공통 | 4~15% | **쓸 수 없다** (FAI34 하한 하나만 남음) |
| GP-009 3일 동일값 | GP-009 77~98% · GP-013 72.9% · GP-014 97.1% · **GP-015 63.6%** | 쓸 수 있다. 합격 오탐 6표본 전부 **0** |

확정된 것: FAI1 상한 · FAI15 상한·하한 · FAI16·17 하한 · FAI34 하한.
미설명 몫은 FAI29·FAI27 처럼 그 표본에서 포화하지 않은 항목의 이탈이며, 표본을 7일로 늘리면 줄어든다.

쏠림: FAI17 하한 38.5% · FAI29 상한 11.4% · FAI16 하한 10.7% · FAI15 하한 9.0% · FAI27 상한 7.4% — 상위 5개가 77%.

## 4. 귀속 규칙 (결정론 · AI 아님)

불량 행 하나마다 원인을 다음으로 정한다.

| 조건 | 귀속 |
| :--- | :--- |
| 확정 한계를 넘은 FAI 가 **1개** | 그 항목 |
| **2개 이상** | 복합 |
| **0개** | 미확정 항목 이탈 |
| FAI 값이 대부분 `0.0` | **측정 실패** — 불량에 두되 근거 유형으로 따로 표기 (결정 10) |

브리핑은 **귀속된 것만** 항목 번호와 한계값으로 말한다.

## 5. AI 의 역할 경계

**숫자는 규칙이 만들고, sLLM 은 문장과 조치 제안만 만든다.**

- 수치 환각이 구조적으로 불가능하다.
- 「추정」 표기는 **조치 제안 문장에만** 붙인다. 근거 칩에는 계산된 값이 그대로 들어간다.
- 브리핑에 **설명률을 함께 표기**한다 — 설비마다 60~98% 로 편차가 크다(§3).
  설명률이 낮아도 원인 지목을 빼지 않는다(결정 11). 60% 여도 「10건 중 6건은 FAI17 하한 미달」이면
  쓸모가 있고, 설명률을 숨기지 않는 편이 과신을 막는다.

### 브리핑이 실제로 쓸 문장

> MQ-008 09-11 불량 11,527건 중 **FAI10 초과 4,546건**(44.7%, 상한 22.880),
> **FAI1 초과 4,337건**(42.6%, 상한 0.040, 평균 +0.0066),
> 미확정 항목 이탈 159건, 측정 실패 21건. 설명률 98.4%.
> → *(추정)* MQ-008 의 FAI10 측정 지점을 우선 점검

### 왜 매번 계산해야 하는가

1위 원인이 표본마다 바뀐다. 사람이 매번 6만 행을 집계해 순위를 내야 한다는 뜻이고,
그것이 결정 3(「정리해 보고하는 데 시간이 걸린다」)의 정체다.

```
MQ-008 09-11 → FAI1 42.0% · FAI10 41.4%
MQ-003       → FAI1 74%
MQ018        → FAI10 36% · FAI2 32%
```

## 7. 필요한 백엔드

### 원천을 직접 읽는다 (결정 13)

사전 집계 테이블과 적재 배치는 **만들지 않는다.** `TB_SAMSUN_DIMENSION` 은 실시간 IO 가 많은 표라
주기적으로 훑는 배치가 원천 장애로 이어질 수 있다. 조회 시점에 MSSQL 을 직접 SELECT 한다.

### 그 대가 — 이 값들은 실측이다

| 작업 | 소요 |
| :--- | ---: |
| S120 하루 전체(21만 행) 측정·불량 수 집계 | **43초** |
| 불량 행만 읽어 확정 한계 위반 집계 | **42초** |
| 브리핑 요건 | 1~2초 |

사전 집계가 없으면 하루치 한 설비가 40초대다. 결정 8(조회 기간 그대로)을 그대로 두면
30일 조회는 수 분이 된다. 다음 네 가지로 버틴다.

| 항목 | 대응 |
| :--- | :--- |
| 원천 부하 | `WITH (NOLOCK)` 으로 읽어 원천 잠금에 영향을 주지 않는다 |
| 반복 조회 | 조회 조건을 키로 **API 애플리케이션 캐시**. 적재 배치가 아니라 "방금 읽은 결과 보관"이라 IO 가 사용자 조회 횟수에만 비례한다 |
| 조회 범위 | **기간 상한**을 둔다. 실측으로 확정(7~14일 예상) |
| 화면 | 표를 먼저 그리고 브리핑은 나중에 채운다(비동기) |

### 한계 세트는 어디에 두나

테이블 3개 중 `ax.tb_aoi_dim_limit`(한계 세트)만은 **원천이 아니라 PostgreSQL 쪽 자산**이라
결정 13 의 대상이 아니다. 다만 지금은 수동 보정 화면을 만들지 않으므로(결정 12),
**한계 세트를 설정으로 들고 시작**하고 테이블은 보정 화면을 만들 때 함께 연다.

한계 재확정(주 1회)도 배치가 아니라 **필요할 때 수동으로 돌리는 조사 작업**으로 둔다.

### API 3건

| # | 내용 |
| :-- | :--- |
| 1 | 집계 조회 — MSSQL 직접 SELECT + 귀속 규칙 적용 + 캐시 |
| 2 | 한계 세트 조회 (설정에서 읽어 그대로 내려줌) |
| 3 | 브리핑 생성 — 1 의 결과를 sLLM 에 넣어 문장으로. **sLLM 호출은 백엔드** |

집계가 내려야 하는 것 — 기간·작업장·설비로 걸러서:
전체 측정 수 / 불량 수 / 불량률 · FAI 번호별 위반 건수와 초과량 합·평균 ·
귀속 유형별 건수 · 설명률 · 직전 동일 기간 대비.

## 8. 남은 것

### 확인이 더 필요한 것

- **GP-015 의 다른 규격이 제품 교체 때문인지** — 더 긴 기간을 봐야 안다.
  바뀌는 것이라면 **세트 버전이 열리는 시점이 곧 제품 교체 신호**가 된다.
- **커버링 인덱스** — 덕우전자 전산 요청 사안. 결정 13 으로 원천을 매번 읽게 되어 **더 중요해졌다.**
  인덱스 추가도 원천 변경이라 같은 이유로 막힌다면, 조회 기간 상한을 더 좁혀야 한다.
- **확정 규칙의 기준값** — 합격 행 20건·7일 창은 7일 표본으로 한 번 더 검증 후 고정.

### 받기로 한 것

- **NAS 경로** — 3층 모달 사진 연결. 지금 설계는 없이도 막히지 않는다.

### 나중으로 미룬 것

- **한계 수동 보정 화면** (결정 12) — 도면 값을 알게 되었을 때 `MANUAL` 로 덮어쓸 자리.
  `/system/metric-standard` 에 붙이는 것이 자연스럽다. 테이블의 `MANUAL` 상태는 지금 만들어 둔다.

### 전제로 두는 것

- **확정 한계는 전체 FAI 의 일부뿐이다** (S120 58개 중 11개). 나머지는 합격 데이터가 규격 끝까지
  닿지 않아 값을 못 박는다. 데이터가 쌓이면 늘어나므로 **주기적 재계산을 전제**로 둔다.
- **FAI 이름은 없다.** 번호와 한계값까지만 말한다. 나중에 현장이 한 개씩 별칭을 달 수 있는 길만
  열어 두면 브리핑이 사람 말로 바뀐다(`/system/glossary`).
