# 덕우전자 AX — 데모 사이트

백엔드 없이 도는 **파일 하나짜리 데모**입니다. 더블클릭해서 바로 보거나, Vercel 에 올려 밖에 보여 줍니다.

산출물은 `dist/index.html` **한 개**입니다(약 15 MB). 글꼴·이미지·화면·더미 데이터가 전부 그 안에 있어
외부 요청이 0건입니다. 그래서 `file://` 로 열어도 그대로 돕니다.

## 만드는 법

```bash
npm run build:proto      # → proto/vercel-demo/dist
```

> **옆의 `proto/` 뿌리에는 다른 데모 프로젝트가 있습니다.**
> `src` 를 통째로 복사한 독립 Expo 앱(자체 `package.json`·`vercel.json`·`dist`)으로, 다른 세션이 만든 것입니다.
> 둘은 접근이 다릅니다 — 그쪽은 **복사본**이라 본 앱을 고치면 따로 맞춰 줘야 하고,
> 이쪽은 **본 앱을 그대로 빌드**하므로 다시 빌드만 하면 따라옵니다. 어느 쪽을 쓸지는 정하셔야 합니다.

## 그냥 보는 법

`proto/vercel-demo/dist/index.html` 을 **더블클릭**하십시오. 서버도 인터넷도 필요 없습니다.

## 올리는 법 (수동)

```bash
npx vercel deploy --prod proto/vercel-demo/dist
```

처음 한 번은 Vercel 이 프로젝트 이름을 묻습니다. 그 뒤로는 같은 명령이 같은 주소로 올라갑니다.
웹 대시보드에서 올릴 때도 **`proto/vercel-demo/dist` 폴더를 통째로** 끌어다 놓으면 됩니다
(빌드 설정 없음 · Output Directory 는 비워 둡니다 — 이미 빌드된 결과물입니다).

화면 이동은 **해시 주소**입니다 — `.../#/quality/aoi` 처럼요. 서버 라우팅 설정이 필요 없는 이유이고,
`file://` 에서도 이동이 되는 이유입니다(`history.pushState` 는 `file://` 에서 막힙니다).

## 이 데모가 실제와 같은 것 / 다른 것

**같습니다 — 화면 코드가 같은 것입니다.**
컴포넌트를 따로 베끼지 않았습니다. 같은 소스를 같은 번들러(Expo/Metro)로 빌드하므로
CSS·레이아웃·글꼴·간격·차트가 사내 화면과 동일합니다. 화면을 고치면 다시 빌드만 하면 따라옵니다.

**다릅니다 — 데이터 계층만 목(mock)입니다.**

| | 사내 | 데모 |
|---|---|---|
| API | 실 서버(Spring) | 목 응답 253건 (`src/services/mock`) |
| 인증 | 실 서버 JWT | 목 — 아무 사번·비밀번호나 통과 |
| MSSQL/MES 원천 | 실 데이터 | 값과 자릿수를 실측에 맞춘 더미 |
| 서버 엑셀 내려받기 | 서버가 전량을 뽑음 | 조회 조건을 담은 안내 파일 |

## 로그인

로그인 화면이 그대로 나옵니다(건너뛰지 않습니다). **비밀번호는 아무 값이나 됩니다.**
사번에 따라 부서가 갈리고, 부서에 따라 보이는 메뉴와 가려지는 수치가 달라집니다.

| 사번 | 계정 |
|---|---|
| `20140901` | 통합관리자 — 전 화면 |
| `20180412` | 품질보증팀 팀장 |
| `20170905` | 생산관리팀 팀장 |
| `20110204` | 경영진 — 수량·수율 비공개(마스킹 확인용) |

로그인 화면에도 같은 안내가 떠 있습니다. 모르는 사번을 넣으면 통합관리자로 들어갑니다.

## 데모 환경변수

`proto/build.cjs` 가 빌드 동안에만 `.env` 에 얹습니다 — 끝나면 원래대로 되돌립니다.

```
EXPO_PUBLIC_USE_MOCK=true         모든 API 를 목으로
EXPO_PUBLIC_LIVE_AUTH=false       인증도 목으로 (서버가 없으므로)
EXPO_PUBLIC_DEMO_AUTOLOGIN=false  로그인 화면을 건너뛰지 않음
EXPO_PUBLIC_MOCK_DELAY=120        로딩 표시가 보일 만큼만 지연
```

## 어떻게 만들어지는가

`expo export` 가 아니라 **esbuild 단일 번들**입니다. Expo 의 정적 내보내기는 라우트마다 HTML 을 만들고
자산을 `/_expo/...` **절대 경로**로 가리켜, 서버에 올리면 돌지만 `file://` 로 열면 아무것도 뜨지 않습니다.
그래서 `app/` 과 `src/` 를 그 자리에서 번들하고 `expo-router` 만 해시 라우터 대체 구현
(`standalone-router.jsx` · 화면이 쓰는 8개 심볼)으로 바꿉니다. **화면 코드는 복사하지 않습니다.**

빌드에서 조심할 것 둘 (고쳐 둔 것입니다):

- 대체 라우터를 `proto/vercel-demo/` 자리에서 번들하면 `proto/node_modules/react` 로 풀려 **React 가 두 벌**
  들어갑니다. react-dom 이 쓰는 React 와 달라져 `ReactSharedInternals.H` 가 null 이 되고 화면이 빕니다.
  빌드가 shim 을 저장소 뿌리로 복사해 넣는 이유입니다.
- 진입점은 대체 라우터를 반드시 `'expo-router'` 이름으로 가져와야 합니다. 상대 경로로 가져오면
  alias 로 들어온 것과 **다른 모듈**이 되어 `Slot` 의 context 가 갈리고, 역시 빈 화면이 됩니다.

## 알아 둘 것

- `proto/vercel-demo/dist` 는 빌드 산출물이라 `.gitignore` 됩니다. 저장소에 올라가지 않습니다.
- 확인은 `file://` 로 8개 화면을 걸어 다니며 했습니다 — 콘솔 오류 0건, 아이콘·그리드(검색칸·너비조절)·우측 AI 패널 모두 정상.
- 데모 데이터의 날짜 기준은 **2026-08-28**(마지막 실적일)입니다. 「오늘 -7일」로 조회하는
  화면(실적 집계 등)은 표본 실적을 조회 구간 위로 옮겨 보여 줍니다 — 언제 열어도 비어 보이지 않습니다.
- 사내 데이터·접속 정보는 번들에 들어가지 않습니다. 목 데이터는 전부 지어낸 값입니다.
